When to stop asking live questions and get a plugin instead

Lessons 1–3 covered the live Q&A path: a Session running, a question or edit answered in the moment. There's a second, separate path — asking Claude to hand you back a complete, installable FH plugin instead. Different tool for a different job: reach for it when you'd run the same question or edit again.

Live question vs. standalone plugin

Live question (Lessons 1–3)Standalone plugin
Needs a Bridge Session? Yes, running throughout No — Claude just hands you text, nothing touches your project until you install and run it yourself
Bound by Access mode? Yes — Read-only/Read-write as chosen at Start No — not bound by either mode at all
Who runs it? Claude, immediately, against your live project You do, under FH's own permission model, whenever you choose
Best for A one-off question or edit, answered now Something you'll want to run again — "list everyone's occupation next to their name", "count how many people have each surname"

Say what you want plainly: "Write me a Report plugin that lists everyone's occupation next to their name" or "Write me a Query plugin that counts how many people have each surname." A Report plugin shows in FH's Report Window; a Query plugin shows a list in the Query Window. Tell Claude which you want.

Why it's not bound by Access mode — and what that means for you

The trade-off, stated plainly

Because you're the one reviewing and running a generated plugin, it can do things a live question never can — even in a Read-write Session — such as showing a message box or reading/writing a file directly. This is intentional, not a gap in the sandbox from Lesson 1: the safety boundary moves from "the sandbox restricts what the script can do" to "you read it before you run it." That review step is now doing the work the sandbox was doing before — don't skip it because "an AI wrote it."

FLAGGED comments: read these before installing

Any line using one of those otherwise-off-limits functions is marked with a -- FLAGGED comment directly above it in the text Claude returns. That's the entire purpose of the flag — a place your eye should stop before you install. Scan for it specifically; don't just skim the whole script and hope you'd notice.

Installing it

Two ways, once you've reviewed it:

  • Manual — save the returned text yourself as a .fh_lua file, then Tools -> Plugins -> New (or Import) in FH, the same way you'd install any plugin.
  • Ask Claude to install it — "install it" / "add it to my plugins" and Claude writes it straight into FH's Plugins folder for you (needs an active Bridge Session, only to look up where that folder is — no Session running, Claude will ask you to confirm the location instead). It never overwrites an existing file: asking again after a tweak adds "V2", "V3", and so on, to both the filename and the plugin's own title.

One FH quirk either way: FH doesn't rescan its Plugins folder while the Plugins Dialog is open — close and reopen Tools -> Plugins afterwards if you had it open, then select the new entry and click Run.
